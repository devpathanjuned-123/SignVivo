# SignVivo

Affordable e-signature platform for small businesses. **Lean MVP**:
upload a PDF, place signature/date/text fields, send to recipients by
email, collect legally-tracked signatures, download the signed PDF +
audit log.

## Stack — Supabase everywhere

| Concern | Service |
|---|---|
| Database | **Supabase Postgres** |
| Auth | **Supabase Auth** (email magic link) |
| Storage | **Supabase Storage** (private `documents` bucket) |
| Access control | **Supabase RLS** (workspace-scoped) |
| Web framework | Next.js 15 (App Router) + TypeScript |
| Styling | Tailwind CSS |
| PDF stamping | pdf-lib (server) |
| PDF rendering | react-pdf + react-signature-canvas (browser) |
| Transactional email | Resend (sign-requests + completion notices) |

No Neon, no Vercel Blob, no NextAuth.

## Quick start

```bash
# 1. Install
npm install

# 2. Set up Supabase (see SUPABASE_DEPLOY.md for the full walkthrough)
#    - Create a project
#    - Run the 4 SQL files under supabase/migrations/ in order

# 3. Configure env
cp .env.example .env.local
# Fill NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY,
#      SUPABASE_SERVICE_ROLE_KEY, RESEND_API_KEY, EMAIL_FROM,
#      NEXT_PUBLIC_APP_URL

# 4. Run
npm run dev
```

## End-to-end test

1. Sign up at `/sign-in` — Supabase emails you a magic link; a
   workspace is auto-created by the signup trigger.
2. Upload a PDF from the dashboard.
3. Add a recipient (name + email), click **Signature** then click on
   the page to place a field. Add a **Date** field too.
4. Click **Send for signature**.
5. In an incognito browser, open the recipient email's link.
6. Sign in the modal, type the date, click **Finish signing**.
7. Back in the sender's dashboard the document shows **COMPLETED** with
   download links for the signed PDF and audit log.

## How access control works

- Every signed-in user belongs to one or more **workspaces**
  (`workspace_members`).
- All domain rows (`documents`, `recipients`, `fields`, `audit_events`)
  are scoped to a workspace, and RLS policies require
  `is_workspace_member(workspace_id)` for read/write.
- **Signers don't have accounts.** The signer page (`/sign/[token]`)
  validates the random `signing_token` server-side and uses the
  service-role Supabase client to read just that recipient's data. RLS
  never sees an anonymous request.
- The `documents` storage bucket is **private**. Sender browsers fetch
  PDFs through short-lived signed URLs generated by the server.

## Repo layout

```
app/                          Next.js App Router pages and API routes
  (app)/                      Authenticated sender app (dashboard, editor, detail)
  auth/callback/              Supabase magic-link code exchange
  auth/signout/               Supabase sign-out
  sign/[token]/               Public signer flow (service-role backed)
  api/                        Document, send, and sign endpoints
components/                   React components (editor, signer, pdf)
lib/
  supabase/server.ts          SSR client (respects RLS)
  supabase/browser.ts         Browser client
  supabase/admin.ts           Service-role client (signer / finalize only)
  supabase/middleware.ts      Session refresh + auth gate
  storage.ts                  Upload, signed-URL, download helpers
  workspace.ts                Default-workspace lookup
  email.ts                    Resend client + email templates
  pdf/render.ts               Stamp fields onto original PDF
  pdf/audit.ts                Generate audit-trail PDF
  pdf/finalize.ts             Orchestrate signed + audit PDFs + emails
supabase/migrations/          0001…0004 SQL files
types/database.ts             Typed `Database` for the Supabase client
middleware.ts                 Refreshes session on every request
```
