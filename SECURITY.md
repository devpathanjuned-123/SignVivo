# SignVivo — Security Model

This document maps each non-negotiable security requirement to the
specific file, policy, or trigger that enforces it. If you change any of
these, update this document in the same PR.

---

## 1. Signers do not need accounts

**Enforcement**
- `/sign/[token]` is the **only** route that talks to anonymous
  visitors. It validates the `signing_token` against the `recipients`
  table using the service-role client, then renders the signing UI.
- The Next middleware ([middleware.ts](middleware.ts)) protects
  `/dashboard` and `/documents/*` only — it deliberately leaves
  `/sign/*` open to anon traffic.
- Recipients are *not* `auth.users` rows. They have no Supabase Auth
  session, no JWT, no cookie. The only credential is the random
  `signing_token`.

**Token properties** ([supabase/migrations/0001_init_schema.sql](supabase/migrations/0001_init_schema.sql))
- 32 random bytes, hex-encoded (256 bits of entropy).
- `unique` constraint at the DB layer.
- `token_expires_at` defaults to 30 days from creation.
- Generated by `gen_random_bytes()` from `pgcrypto`, so the app server
  never has to seed an RNG.

**Replay guard** ([app/api/sign/[token]/route.ts](app/api/sign/[token]/route.ts))
- Once `recipients.status = 'SIGNED'`, the submit endpoint returns 409.
- The page route returns "Already signed" instead of re-rendering the
  signing UI.
- Expired tokens return 410.

## 2. All PDFs remain private

**Bucket configuration** ([supabase/migrations/0004_storage.sql](supabase/migrations/0004_storage.sql))
- The `documents` bucket is created with `public = false`.
- Allowed MIME types are restricted to `application/pdf`,
  `image/png`, `image/jpeg`.
- Storage RLS gates every read/write on workspace membership
  (`is_workspace_member((storage.foldername(name))[1]::uuid)`).

**Browser access** ([lib/storage.ts](lib/storage.ts))
- The browser **never** receives a public Storage URL or a storage
  path. The server generates short-lived **signed URLs** (default 30
  minutes; 7 days for completion emails) and passes those to the
  client.
- For the editor view, the URL is created via the SSR client, so the
  signed URL respects RLS.
- For the signer view, the URL is created via the service-role client
  (anonymous traffic), but issued only after the `signing_token` check
  succeeds.

**Anti-leak in code review**: searching the codebase for `getPublicUrl`
should return zero hits. If you ever need that API, document why.

## 3. Service role key never reaches the browser

**Three independent defenses, in order of strictness:**

1. **Env-var naming** ([.env.example](.env.example)): the key is
   `SUPABASE_SERVICE_ROLE_KEY` — no `NEXT_PUBLIC_` prefix. Next.js
   refuses to inline non-public env vars into client bundles.
2. **`import "server-only"`** ([lib/supabase/admin.ts](lib/supabase/admin.ts)
   and [lib/audit.ts](lib/audit.ts)): if any client component
   transitively imports either of these files, the Next.js build
   fails. This is the **build-time** guarantee.
3. **Runtime guard**: `getSupabaseAdminClient()` throws immediately if
   `typeof window !== "undefined"`. This is the **runtime** guarantee —
   if a future refactor smuggles the import past the build check
   (e.g. dynamic import), the page crashes loudly instead of silently
   shipping a key.

**Files that may import the admin client:**
- [app/api/sign/[token]/route.ts](app/api/sign/[token]/route.ts) (anon signer flow)
- [app/api/documents/route.ts](app/api/documents/route.ts) (transitively, via the audit helper)
- [app/api/documents/[id]/send/route.ts](app/api/documents/[id]/send/route.ts) (same)
- [app/sign/[token]/page.tsx](app/sign/[token]/page.tsx) (anon signer page)
- [lib/audit.ts](lib/audit.ts)
- [lib/pdf/finalize.ts](lib/pdf/finalize.ts) (background finalize)

Anywhere else that calls `getSupabaseAdminClient()` is a code-review red
flag.

## 4. Workspace isolation via Row-Level Security

**Every domain table has RLS enabled and a workspace-scoped policy.**

| Table | Policy file | Predicate |
|---|---|---|
| `profiles` | [0002_rls_policies.sql](supabase/migrations/0002_rls_policies.sql) | `id = auth.uid()` |
| `workspaces` | same | `is_workspace_member(id)` |
| `workspace_members` | same | `user_id = auth.uid() OR is_workspace_member(workspace_id)` |
| `documents` | same | `is_workspace_member(workspace_id)` |
| `recipients` | same | `is_workspace_member(document_workspace(document_id))` |
| `fields` | same | `is_workspace_member(document_workspace(document_id))` |
| `audit_events` | same | `is_workspace_member(document_workspace(document_id))` (SELECT only) |
| `storage.objects` (bucket `documents`) | [0004_storage.sql](supabase/migrations/0004_storage.sql) | `is_workspace_member((storage.foldername(name))[1]::uuid)` |

`is_workspace_member()` is a `security definer` function that reads
`workspace_members` directly, so it bypasses recursion problems and
runs in O(1) with a covering index on `(workspace_id, user_id)`.

**Anti-leak verification query** — run after every migration:

```sql
select tablename
  from pg_tables
 where schemaname = 'public'
   and tablename not in (
     select tablename from pg_policies where schemaname = 'public'
   );
```

If this returns any rows, a domain table is missing RLS and the
migration is incomplete.

## 5. Audit events are immutable and backend-generated

**Backend-generated** ([supabase/migrations/0005_hardening.sql](supabase/migrations/0005_hardening.sql))
- `revoke insert, update, delete on public.audit_events from anon, authenticated`.
- No `INSERT` policy is defined — even if a future migration accidentally
  grants the privilege back, RLS would still block writes.
- All writes go through [lib/audit.ts](lib/audit.ts), which uses the
  service-role client. The helper validates the payload with Zod and
  is `server-only` (cannot be imported from a client component).

**Immutable**
- `0005_hardening.sql` installs two triggers:

  ```sql
  create trigger audit_events_no_update before update on public.audit_events ...
  create trigger audit_events_no_delete before delete on public.audit_events ...
  ```

  Both call `prevent_audit_modification()`, which raises an exception
  with SQLSTATE `42501` (`insufficient_privilege`). Triggers fire for
  **every role**, including `service_role`. The only way to bypass
  them is to drop the triggers explicitly — that change is visible in
  git history.

**Operational check** — to confirm immutability is live:

```sql
-- This should raise: "audit_events rows are immutable: UPDATE is not permitted"
update public.audit_events set type = 'DOWNLOADED' where id = (
  select id from public.audit_events limit 1
);
```

## 6. End-to-end signing workflow

Putting it all together — what crosses what trust boundary, and where.

```
┌──────────────────────────────────────────────────────────────────────┐
│ Sender (authenticated)                                               │
│   ⇆ middleware.ts (refresh session, gate /dashboard, /documents)     │
│   ⇆ Server Component / Route Handler                                 │
│       → SSR client (lib/supabase/server.ts)                          │
│         → Postgres + Storage with auth.uid() — RLS scoped            │
│       → audit helper (lib/audit.ts)                                  │
│         → service-role client (lib/supabase/admin.ts) — server-only  │
│           → INSERT into audit_events (only writer path)              │
└──────────────────────────────────────────────────────────────────────┘
                              │
                              │   email with /sign/{token}
                              ▼
┌──────────────────────────────────────────────────────────────────────┐
│ Signer (anonymous)                                                   │
│   ⇆ /sign/[token]/page.tsx                                           │
│       → service-role client (server-only)                            │
│         → SELECT recipients WHERE signing_token = ?                  │
│         → createSignedUrl() for original PDF (30 min)                │
│       → logAuditEvent('VIEWED') via service-role client              │
│   ⇆ /api/sign/[token]/route.ts                                       │
│       → service-role client (server-only)                            │
│         → status / expiry / replay checks                            │
│         → size caps on values                                        │
│         → UPDATE fields, recipients                                  │
│         → logAuditEvent('SIGNED')                                    │
│         → finalizeIfReady() in background                            │
└──────────────────────────────────────────────────────────────────────┘
                              │
                              │   when all recipients = SIGNED
                              ▼
┌──────────────────────────────────────────────────────────────────────┐
│ finalize.ts (server-only background)                                 │
│   → service-role client                                              │
│   → download original from Storage                                   │
│   → pdf-lib stamp fields → upload signed.pdf                         │
│   → generate audit.pdf → upload                                      │
│   → logAuditEvent('COMPLETED')                                       │
│   → mark document COMPLETED                                          │
│   → Resend notifications with 7-day signed URLs                      │
└──────────────────────────────────────────────────────────────────────┘
```

Two trust boundaries to keep crisp:
- **Browser ↔ server**: nothing crosses this boundary that the user
  isn't already authorized to see. PDFs go via signed URLs; tokens go
  via Supabase Auth cookies; service-role keys never cross.
- **Authenticated ↔ anonymous server paths**: anonymous routes
  (`/sign/*`) use the service-role client because they can't satisfy
  RLS. The compensating control is that they validate the
  `signing_token` *before* any read or write.

## 7. Quick-look checklist before merging

- [ ] No `getPublicUrl` calls anywhere.
- [ ] No `process.env.NEXT_PUBLIC_SUPABASE_SERVICE_ROLE_KEY` (misnamed
      env var would leak the key into the client bundle).
- [ ] Every new table has an RLS policy in
      `supabase/migrations/0002_rls_policies.sql`.
- [ ] Every audit write goes through `logAuditEvent()` — grep for
      direct `audit_events` INSERTs.
- [ ] The `lib/supabase/admin.ts` import list (under
      "Files that may import the admin client" above) is up to date.
